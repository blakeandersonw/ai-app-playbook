# 05 · AI: DeepSeek via OpenRouter, GPUs at volume

> **Default:** **DeepSeek** via **OpenRouter**, behind Cloudflare **AI Gateway**. Pick models with **Artificial Analysis** and your own evals. At volume, run custom workflows on **Vast.ai / RunPod** GPUs.
> **Agent: read this when** adding or changing any model call or prompt.

## Setup

```
client ──▶ Worker (auth · quota · rate limit) ──▶ AI Gateway ──▶ OpenRouter ──▶ DeepSeek (or another model)
                         │
                         └── ai_call event (model, tokens, latency, cost) ──▶ Tinybird
```

- **[OpenRouter](https://openrouter.ai):** one key, one OpenAI-compatible API, provider fallbacks.
- **[AI Gateway](https://developers.cloudflare.com/ai-gateway/usage/providers/openrouter/):** caching, logs, rate limits, spend analytics.
- Never call models from a client. Keys stay in the Worker.

## Models

`deepseek/deepseek-v4.1-flash-1017` on OpenRouter: about **$0.15 / $0.60 per million tokens in/out** (Oct 2026). A 1,500-in / 400-out call costs about **$0.0005**. Two calls a day is about **$0.03/month** per subscriber, against $2.50/month revenue at $30/year.

| Task | Model |
|---|---|
| Classify, extract, summarize, chat, plans | **DeepSeek** (default) |
| Photos (meal, plant, homework, skin) | Cheapest vision model that passes evals on your real photos |
| The answer users judge you on, if DeepSeek fails evals | A frontier model, on that route only |

Step up only when evals justify it. Keep model ids in **KV or env vars** so switching needs no deploy.

## Choosing a model: Artificial Analysis

[Artificial Analysis](https://artificialanalysis.ai) compares models on quality, speed, and price.

| Need | Leaderboard |
|---|---|
| Text → text | [LLM leaderboard](https://artificialanalysis.ai/leaderboards/models) · [providers](https://artificialanalysis.ai/leaderboards/providers) |
| Text → image | [Text-to-image](https://artificialanalysis.ai/text-to-image) · [arena](https://artificialanalysis.ai/text-to-image/arena) |
| Text / image → video | [Text-to-video](https://artificialanalysis.ai/video/leaderboard/text-to-video) · [image-to-video](https://artificialanalysis.ai/video/leaderboard/image-to-video) |
| Speech → text (ASR) | [Speech-to-text](https://artificialanalysis.ai/speech-to-text) |
| Text → speech (TTS) | [Text-to-speech](https://artificialanalysis.ai/text-to-speech) |

1. Shortlist the 2–3 cheapest models near the top for your task.
2. Check speed (tokens/sec and time to first token; seconds per image or clip).
3. Run your own evals on the shortlist. They decide.
4. Note which have **open weights** (self-hostable later).

## Rules

1. Stream everything.
2. Every call gets a timeout and a fallback model (OpenRouter `models: [primary, fallback]`).
3. Log every call (`ai_call`): user, feature, model, tokens in/out, latency, cost, success.
4. Cap spend per user on the server: daily quota for trials, fair-use ceiling for subscribers, in D1 or a Durable Object.
5. Prompt caching: stable system prompt first, user content last.
6. Prompts live in `prompts/*.md` in git.
7. Model output is untrusted. Validate JSON; sanitize anything rendered.
8. Text the model reads is data (prompt injection). Tools that take actions need confirmation.

## Evals

- 20–100 real inputs with what "good" looks like.
- Score quality, latency, cost per candidate. Run by hand, not in CI.
- Switch only when the numbers say so.

## GPUs: Vast.ai / RunPod

Use when an API can't do the job or volume is large.

| Workflow | Building blocks |
|---|---|
| **Speech → text (ASR)** | [faster-whisper](https://github.com/SYSTRAN/faster-whisper) and other open ASR models |
| **Image generation / editing** | Open image models via [ComfyUI](https://github.com/comfyanonymous/ComfyUI) or a small Python server |
| **Self-hosted LLM** | Open-weight models (DeepSeek and others) on [vLLM](https://docs.vllm.ai) or [SGLang](https://docs.sglang.ai) |
| **Video, voice, TTS, upscaling** | Open models from the Artificial Analysis boards |

- **[Vast.ai](https://vast.ai):** GPU marketplace, usually cheapest per GPU-hour; steady high-volume work. ([pricing](https://vast.ai/pricing) · [docs](https://docs.vast.ai))
- **[RunPod](https://www.runpod.io):** always-on pods and **[serverless](https://docs.runpod.io/serverless/overview)** that scales to zero; spiky jobs. ([pricing](https://www.runpod.io/pricing))

A rented GPU costs the same per hour at 10 or 10,000 requests. Once a workflow keeps a GPU busy most of the day, self-hosting is often several times cheaper than the API, sometimes 10x. Below that, APIs are cheaper.

1. Start on APIs. Move a workflow to GPUs when its bill is large and steady, or the API can't do it.
2. GPU boxes only run models. Routing, queues, retries, auth, quotas, billing stay on Cloudflare; a Worker calls the GPU endpoint.
3. Keep an automatic fallback to OpenRouter or a hosted API.
4. Track cost per result (image, audio minute, 1k tokens) for both paths in Tinybird.
5. Package each workflow as a container image with pinned weights.
6. Autoscale on queue depth.
